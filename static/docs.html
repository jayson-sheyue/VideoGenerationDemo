接口与状态

Interactions API 参考 请求字段：model、input、response_format、generation_config、store、background、previous_interaction_id、seed。 Interactions 开发指南 有状态 / 无状态。无状态不能用 previous_interaction_id，也不能 background。 Interactions 概览 默认 store=true，保留约 7 天。Omni 只走这条 API，不走 generateContent。 Gemini API 视频入口 开发者向的总页。Veo 3.1 Preview 已关闭，文档指向 Omni。

放大和 Transcoder API

Omni 的 upscale 做的就是把一条已经生成的短片提到更高分辨率。 VideoGenerationModelParams 对 task=upscale 的定义是 “Upscale a video to a higher resolution”。 1.2 模型卡片 把它写成 standalone video upscaling：输入最长 15 秒，输出仍是 16:9 或 9:16 的 Omni 成片。 GA 公告 的用法是先用 360p 或 720p 出草稿，再把选定的成片放大到 1080p 或 4K。 它不接受文字，所以不能顺便改画面、运镜或对白；时长和画幅跟源片走。

Cloud Transcoder API 是另一条媒体处理流水线。它改的是容器、码率、编码参数、HLS / DASH、裁剪、贴片、HDR、加密和缩略图。 那里的分辨率变化是重新采样再编码，不经过 Omni，也不受 15 秒和 16:9 / 9:16 的生成限制，适合长片分发。 本 Demo 不调用 Transcoder。

本 Demo 怎么对应

  • 实验台右上角可换模型。自定义 ID 会原样发给接口，控件按 ID 里是否包含 1.2 来套用上限。
  • Generate 的四种任务、Continue / Edit、Extend 都还在。1.2 的 Continue / Edit 默认走多轮 interaction，且这一轮不带 video_config.task；取消勾选就改回重传 gs://。Extend 始终重传成片并带 task=extend。
  • 切到 Extend 时，实验台说明官方任意长度，并在源片超过约 24 秒时拦住。单次新增永远是 3–10 秒，成片约 ≤ 40 秒。
  • References 可以再挂最多 3 段参考视频。编辑和续写在 1.2 上可以再挂最多 2 张参考图。
  • Upscale 只发给 1.2，并且重传成片、带 task=upscale。源片超过 15 秒会在提交前拦住。目标分辨率按官方阶梯：360p → 720p/1080p，720p → 1080p/4k，1080p → 4k 不支持。提示词框会藏起来，请求不带 type: text。
  • Seed 和 labels 只在 1.2 上出现。labels 要用小写的 key=value。
  • 1.2 请求带 store: true 和 background: true，页面仍轮询任务。取消页面等待不会取消已经提交、仍可能计费的生成。

文档写了、这里不做成按钮的

  • 音频参考：模型卡片写 Audio 输入不支持，Cloud 博客写需要 allowlist。没有可点的上传，避免把未开通的请求当成可用功能。
  • 改配音、改台词：Gemini API 写明 voice editing 不支持。画面编辑可以，声音不行。
  • 流式 thoughts（stream: true）：文档有，本 Demo 仍等成片后再显示 thoughts。
  • 系统指令、函数调用、生图、URL context：模型卡片均为不支持。
  • 成片带不可见的 SynthID，模型卡片同时支持 C2PA。这是输出属性，没有单独开关。

仓库里的 learning_guide.md 把这些限制写得更细，并注明本 Demo 对 response_format 的裁剪（编辑不传 duration，续写不传 aspect_ratio）。
